# Care Pathway AI 🩺

An AI-assisted healthcare decision-support **mobile application** that analyzes user-provided symptoms and generates structured care-pathway guidance using **Google Gemini**.

> **Disclaimer:** Care Pathway AI provides AI-assisted guidance for informational purposes only. It is not a medical diagnosis or a replacement for a qualified healthcare professional. Users should seek professional medical help for severe, worsening, or emergency symptoms.

---

## Overview

Care Pathway AI is a Flutter mobile application backed by an ASP.NET Core Web API. Users enter their symptoms, and the backend sends them to Google Gemini, which returns a structured care-pathway response. The app displays the results with risk assessment, safety advice, care steps, and matched factors.

The application is designed with safety in mind and explicitly identifies situations where urgent medical attention may be required.

---

## Key Features

- **AI-Powered Symptom Analysis** — Symptom input is sent to Google Gemini, which generates structured care-pathway guidance
- **Risk & Emergency Assessment** — Each analysis includes a risk score (0–100) and triage level (Emergency, Urgent, Moderate, Non Emergency)
- **Possible Condition / Concern** — A short description of the symptom concern (not a diagnosis)
- **Safety Advice** — Disclaimer and safety guidance accompanying every result
- **Care Steps** — Practical, conservative care steps generated by the AI
- **Matched Factors** — Relevant factors from the user's input that contributed to the pathway
- **Red Flags** — Urgent warning signs identified during analysis
- **Follow-Up Reminders** — Users can schedule local notifications to revisit their care steps
- **Analysis History** — Previous analyses are stored and can be reviewed
- **User Profiles** — Age, gender, blood group, existing conditions, medications, allergies, and emergency contacts
- **Medication Reminders** — Daily scheduled reminders for medications
- **Authentication** — Email/password registration and login with BCrypt password hashing
- **SOS Breathing Screen** — Guided breathing exercise for emergency situations
- **Health Insights** — Health metrics and insights dashboard
- **Structured AI Responses** — Gemini returns JSON constrained by a response schema
- **Safe Fallback Handling** — If Gemini is unavailable, the backend returns a rule-based safety result

## AI Integration

The current AI provider is **Google Gemini**. The pipeline:

```text
Flutter (symptom input)
    ↓ HTTP POST
ASP.NET Core Web API
    ↓ ICarePathwayService
GeminiCarePathwayService
    ↓ HTTP POST (structured JSON request)
Google Gemini API
    ↓ Structured JSON response
ASP.NET Core Web API
    ↓ JSON
Flutter (care-pathway UI)
```

The Gemini API key is kept **server-side only**. It is never included in the Flutter application, APK, or client-side code.

### AI Response Fields

Gemini returns structured JSON matching the `CarePathwayResponse` model:

| Field | Type | Description |
|---|---|---|
| `triageLevel` | string | One of: Emergency, Urgent, Moderate, Non Emergency |
| `riskScore` | integer | 0–100 |
| `possibleCondition` | string | Short description of the symptom concern |
| `recommendedAction` | string | What the user should do next |
| `safetyAdvice` | string | Disclaimer and safety guidance |
| `matchedFactors` | string[] | Relevant factors from the input |
| `redFlags` | string[] | Urgent warning signs if any |
| `careSteps` | string[] | Practical conservative care steps |

## API Endpoints

### Care Pathway

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/care-pathway/analyze` | Submit symptoms and receive AI-generated care pathway |
| `GET` | `/api/care-pathway/history` | Get analysis history (optional `?userId=`) |
| `GET` | `/api/care-pathway/history/{id}` | Get a specific analysis by ID |

### Authentication

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/auth/register` | Register a new user account |
| `POST` | `/api/auth/login` | Login with email and password |
| `POST` | `/api/auth/save-fcm-token` | Save Firebase Cloud Messaging token |

### Profile

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/profile` | Create or update user profile |
| `GET` | `/api/profile/{userId}` | Get user profile by ID |

## Local Setup

### Prerequisites

- **Flutter SDK** — for building and running the mobile app
- **.NET 10 SDK** — for building and running the backend
- **SQL Server** — LocalDB (included with Visual Studio) or a SQL Server instance
- **Google Gemini API key** — get one at [aistudio.google.com/apikey](https://aistudio.google.com/apikey)

**Ollama is not required.** The application uses Google Gemini as its AI provider.

### Backend Setup

1. Navigate to the backend project:

```bash
cd backend/CarePathwayApi
```

2. Configure the Gemini API key using .NET user secrets:

```bash
dotnet user-secrets set "AI__Gemini__ApiKey" "YOUR_GEMINI_API_KEY"
```

3. (Optional) Configure the Gemini model and base URL:

```bash
dotnet user-secrets set "AI__Gemini__Model" "gemini-3.8-flash"
dotnet user-secrets set "AI__Gemini__BaseUrl" "https://generativelanguage.googleapis.com/v1beta/models"
```

4. Run the backend:

```bash
dotnet run
```

The API will be available at `http://localhost:5193`.

### Flutter Setup

1. Navigate to the Flutter project:

```bash
cd mobile_app
```

2. Install dependencies:

```bash
flutter pub get
```

3. Run the application:

```bash
flutter run
```

### API Base URL Configuration

The Flutter app supports configuring the backend URL via `--dart-define`:

```bash
# Local development (default)
flutter run

# Custom backend URL
flutter run --dart-define=API_BASE_URL=https://your-api-domain.com

# Production
flutter run --dart-define=API_BASE_URL=https://your-deployed-api.com
```

If `API_BASE_URL` is not set, the app defaults to:
- **Web (Chrome):** `http://localhost:5193`
- **Mobile (Android):** `http://192.168.1.6:5193` (update the LAN IP in `api_config.dart` if needed)

## Deployment

The application is designed for cloud deployment without requiring users to install a local AI model.

```text
User's Flutter App
       │
       │ HTTPS
       ▼
Hosted ASP.NET Core API
       │
       │ Gemini API (server-side key)
       ▼
Google Gemini
```

### Backend Deployment Checklist

- [ ] Set `AI__Gemini__ApiKey` as an environment variable or hosting-provider secret
- [ ] Set `AI__Gemini__Model` to your preferred Gemini model
- [ ] Configure `ConnectionStrings__DefaultConnection` for your production SQL Server
- [ ] Set `Cors__AllowedOrigins` to your frontend domain(s)
- [ ] Ensure HTTPS is enabled in production
- [ ] Do not commit `appsettings.json` with real secrets to source control

### Flutter Production Build

```bash
flutter build apk --release --dart-define=API_BASE_URL=https://your-api-domain.com
# or
flutter build web --release --dart-define=API_BASE_URL=https://your-api-domain.com
```

## Security

- The Gemini API key is **server-side only** — it is never included in Flutter code, assets, or APKs
- Secrets must not be committed to Git — use environment variables or hosting-provider secrets
- The `.gitignore` excludes `google-services.json`, `GoogleService-Info.plist`, `*.env`, and `*.env.*`
- Passwords are hashed with BCrypt before storage
- Sensitive patient information should not be logged unnecessarily
- Production deployments should use HTTPS and restrict CORS origins

---

## Safety & Fallback Handling

The application does not rely exclusively on the availability of the AI provider.

If the Gemini service becomes unavailable, the backend uses a rule-based fallback (`CarePathwayService`) that provides safe, conservative guidance based on keyword matching. This fallback is clearly identifiable in logs and is never presented as an AI-generated response.

The application also maintains emergency safety messaging and advises users to seek professional medical assistance when symptoms are severe, worsening, or potentially life-threatening.
